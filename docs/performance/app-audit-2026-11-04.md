## Ranked findings

1. **Fixed: rehab-label generation repeatedly runs NLP over controlled bank labels.** Profiling an injury-history plan-detail route found 756 `_canonical_region` calls, consuming 2.813 of 2.851 profiled seconds. There are 755 bank rows but only 32 unique location labels. The fix uses the existing `LOCATION_MAP` for curated bank labels, handles `unspecified` as unlocalized, and retains the original NLP fallback for unknown labels. Athlete free text still uses NLP. Live injury flags are still fetched every time. No clinical thresholds, readiness decisions, cache lifetimes or writes change. This shared helper affects plan-detail responses, including responses returned by plan changes. A profiled final route took 50 ms with one remaining NLP call. Profile overhead is included in both figures; paired unprofiled evidence is recorded separately below.
2. **Remaining: Today injury-policy work.** A separate profile found 0.851 s total with 0.450 s under `_with_injury_policy`, 0.285 s loading/composing clinical policies, and 41 NLP pipeline invocations. Components overlap and must not be summed. This is local CPU work, not measured SQL latency. Clinical policy compilation and repeated free-text assessment deserve a separate change with output-equivalence tests; this patch does not cache safety decisions.
3. **Remaining: startup admission and profile work.** `AuthProvider` checks Supabase signup admission before exposing the session; `/api/me` then reads intake and plan summaries. Initial Home can overlap its Today/plan reads once the session exists. Admission is a security/access boundary and is not removed.
4. **Remaining: admin request sequencing.** Directory reads are sequential; the job monitor awaits four independent endpoints. The backend deliberately limits concurrent admin requests to two. Measure queue time and backend saturation before parallelising these screens.
5. **No duplicate GET found in the central browser journey.** Existing sharing already removes repeated plan-detail requests. Save helpers keep confirmation behind successful HTTP responses; exercise logs and profile settings use returned saved rows rather than mandatory refetches. Completion/check-in and injury flows intentionally refresh authoritative state. Unbounded broad cache reuse or fire-and-forget clinical saves would change correctness.

## Home and Today shared-read decision

Both deliberately request fresh `/api/today`, sharing only concurrent identical requests. The existing 30-second reuse policy is reserved for plan labels/links; the command view also includes training-day, readiness and injury holds. Writes invalidate the shared client cache before and after the request, with sharing disabled during writes. This covers this browser, but not another device, time advancing across a training-day boundary, or server-side changes. This patch leaves fresh Home/Today reads in place. Presentation plan detail already reuses fresh Home reads in Today and Plan Viewer. The measured CPU bottleneck can be removed without weakening these rules.

## Measurement gaps and targets

- Repeat navigation under 1 s and Home under 1.5 s: desktop fixture medians mostly meet them; Home has an observed 1.756 s sample. These are not production guarantees.
- Simple saves under 500 ms / complex saves under 1 s: unverified live. Clinical validation, XP reconciliation and mandatory authoritative reads can exceed these budgets; do not acknowledge a failed/unconfirmed write to meet a target.
- `Server-Timing` separates auth/profile/app in a live request; `UNLXCK_READ_DIAGNOSTICS=1` gives backend Data API attempt durations/counts. Data API time includes HTTP/PostgREST and is not SQL execution time. PostgreSQL execution must be measured independently and matched to an observation window.
- Live network RTT, auth/profile timing, browser render-only timing, actual server cold starts, full mobile bandwidth throttling, cross-device mutations and every role-specific save remain unmeasured. No live URL/account/log source was available. No unsupported app-wide production speed claim is made.
